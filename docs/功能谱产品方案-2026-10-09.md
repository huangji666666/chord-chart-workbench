# 轻谱：功能谱网页产品方案（待确认）

日期：2026-10-09。临时产品名：轻谱。

**开源优先修订**：根据用户追加要求，选型与格式以同目录《开源选型与产品对标-2026-10-09.md》为准。优先复用现有记谱格式、解析器、排版引擎、播放器、指法资源和设计素材；先前逐音符 JSON 仅保留为讨论记录，不作为已确定方案。

本轮交付为产品方案与 AI 识谱协议草案。界面示意图用于讨论视觉方向，不代表可运行页面。本文列出的新增能力尚未实施或验收。

## 1. 产品目标

在手机、平板、电脑浏览器上，完成「新建或导入 → 修改 → 试听 → A4 导出 → 曲库管理」。优先服务吉他弹唱、排练和现场看谱。

默认打开一张干净的谱。常用操作直接可见，复杂设置按需展开。完整能力分阶段补齐，避免把所有字段同时放到首页。

## 2. 当前目录的可复用基础

根据当前 README.md、docs/SPEC.md、docs/HANDOFF.md 的记录，已有工作台包含和弦/级数显示、点按编辑、歌词、自由文字块、自动保存、撤销重做、曲库、主题、工程文件及 PDF/图片导出。

这些是文档记录，本轮未运行现有程序或复核历史测试。旧文本语法不携带歌词，重新应用文本会清空歌词；旋律简谱和播放也不在旧规格范围内。下一轮应先检查实际代码，再确定复用和迁移方案。

新导入协议不得直接覆盖旧工程格式。必须通过转换层，保留原工程和旧歌词/文字块；导入默认新建曲谱，替换当前曲谱时先留快照。

## 3. 页面与操作

### 平板和电脑

- 顶栏：曲名、保存状态、撤销/重做、试听、导出。
- 左侧可收起：谱库与 AI 导入。AI 导入包括复制提示词、粘贴结果、检查预览三个步骤。
- 中央：A4 竖版纸张。页首为歌名、作者、原调/选调、变调夹、拍号、速度和备注。
- 点击和弦、歌词、音符或小节，出现对应的小面板；未选中时不常驻堆满设置。
- 右上角「外观」集中管理主题、字体与版式。

### 手机

- 底部只有谱库、编辑、播放、更多四个入口。
- 左栏改为抽屉；详细编辑使用底部面板。
- 编辑模式按屏幕宽度排小节，保证容易点选。
- A4 预览单独按固定纸张布局显示，支持缩放；导出保持纸张版式，不受手机宽度影响。
- 演出模式隐藏编辑按钮，提供大字、手动翻页/滚动与可选自动滚动。

## 4. 能力范围

| 模块 | 建议能力 | 默认呈现 |
| --- | --- | --- |
| 曲谱信息 | 标题、作者、调性、调式、变调夹、拍号、速度、备注 | 一行摘要，点开编辑 |
| 和弦 | 和弦名、数字级数、罗马级数、双行显示，转调，斜杠和弦 | 大字和弦或级数 |
| 歌词 | 按字/词/短句对齐，字号比例、行距、断行、移动锚点 | 和弦下方 |
| 简谱 | 有源旋律时导入；音高、八度、时值、休止、附点、连音；可隐藏 | 默认关闭，无内容不占行 |
| 编辑 | 段落、小节增删复制、重复标记、撤销重做、未保存提示 | 选中后出现 |
| 试听 | 和弦试听、和声循环、节拍器、变速、旋律独奏/伴奏组合 | 底部轻量播放条 |
| 曲库 | 文件夹、收藏、标签、搜索、改名、复制、回收站、排序 | 最近编辑优先 |
| 演出 | 自定演出曲序、全屏阅读、字号调整、滚动 | 后续增强 |

“完整”不等于首版支持全部复杂记谱。五线谱、完整六线谱、指法自动编配、音频转谱、专业录音混音不列入本次核心目标；如后续需要，可独立立项。

## 5. 必须正确的音乐规则

### 和弦、旋律、歌词独立保存

内部以「歌曲 → 段落 → 小节 → 拍点」组织。和弦轨、旋律轨、歌词轨使用相同时间轴，各自保留内容和时值。不能只把一串歌词粗略挂在一个和弦上作为唯一数据结构，否则一字多音、切分和换和弦位置会受限制。

对于原图没有节奏信息的弹唱谱，允许只保存和弦与歌词的文字锚点，不编造拍点。之后可手动补拍点。

### 显示切换与实际改谱不同

- 显示切换仅改变写法：例如 C 大调的 C / Am / F / G 可显示为 1 / 6m / 4 / 5，罗马写法为 I / vi / IV / V。
- 实际转调会改变音高，保留和声关系。
- 变调夹会影响吉他实际发声音高，必须区分原调、指型调、实际调，避免重复升调。
- 不确定调号或调式时保留原标记，不自动猜级数。
- 数字级数要约定大小和弦写法及小调的级数基准。导入保留来源记法，不把所有小调谱强行套到大调规则。
- 旋律简谱的“1=某音”单独记录，不能直接假定等于歌曲主音或吉他指型调。

### 试听的真实性

- 没有旋律时，可以试听和弦；不能从歌词和和弦恢复原曲旋律。
- 没有节奏时，可由用户启用“均分节奏试听”，界面明确标示为练习节奏。
- 有可信拍点时，按真实时值播放并高亮当前小节/歌词。
- 原图未提供的扫弦/分解伴奏可作为用户选择的练习模板，不能冒充原曲编配。

## 6. AI 导入方案

用户流程：打开 AI 导入 → 复制统一提示词 → 将提示词和谱图发给支持图片输入的外部 AI → 复制它返回的代码块 → 粘贴 → 检查 → 导入为新曲谱。

建议界面仍使用 **Markdown 代码块内的固定 JSON 外壳**，但乐谱正文直接采用现成 ChordPro / Sparks NMN 格式。ChordMark 列入和声节奏格式比较。用户只复制粘贴，不需要学习 JSON。最初的 `AI识谱提示词-v1草案.md` 已标为暂缓采用，新方向见 `AI识谱提示词-开源格式方案.md`。

选择理由：现成记谱格式已解决大量和弦、歌词与时值表达问题；小型 JSON 外壳只负责格式标识、版本和疑点。Markdown 表格及空格对齐容易在聊天复制、换行或字体变化后产生歧义。代码块只是方便一键复制的外壳。

这是一份自定义交换协议，不是外部软件已经支持的行业标准。其目标是在能遵循提示词的多模态 AI 之间使用同一说明，并由本程序校验；识图准确率与格式遵循率不能保证百分之百。

导入器应做到：

1. 接受纯 JSON 或唯一完整 JSON 代码块，忽略前后说明；多个候选时让用户选。
2. 校验版本、字段类型、调号、和弦、时间范围、引用关系与重复 ID。
3. 容忍换行差异、BOM、外围空白等无损差异；不擅自改写歌词中的标点或损坏的结构。
4. 区分“可以导入但待确认”和“结构无法解析”。已识别部分不因一个音符看不清而全部报废。
5. 用「主歌第 3 小节：第 2 个和弦待确认」这样的定位方式提示问题。
6. 导入预览显示曲名、段落、小节、是否包含歌词/简谱与待确认项。
7. 保留原始文本和导入前快照。错误时不覆盖当前谱子。
8. 不支持的版本明确说明；新版本经过迁移后再使用，避免静默丢字段。

兼容入口可增加标准 ChordPro 的歌词与和弦基本语法，如 `[C]微风[Am]经过窗前`。这适合已有纯弹唱谱，但完整的旋律、逐拍时值、疑点标记仍使用主 JSON 协议；不宣称自定义协议等于 ChordPro。

参考：
- ChordPro 官方格式介绍：https://chordpro.org/chordpro/chordpro-introduction/
- ChordPro 官方指令：https://www.chordpro.org/chordpro/chordpro-directives/

## 7. 视觉与排版

默认使用暖纸白和低饱和绿色。可选纸黄、浅绿、纯白、白蓝，后续按需增加深色演出模式。舒适感是视觉设计目标，不作医疗意义的护眼承诺。

界面主题与导出纸色分开设置：屏幕可用浅绿，打印可单独选择纯白省墨。字体给少量清晰选择：现代黑体、书页宋体，以及适合数字对齐的等宽字体。歌词、和弦、简谱分别有字号比例，提供“小/中/大”预设，更多设置中再开放精确数值。

A4 竖版为 210 × 297 mm。支持页边距、每行小节数、段落间距、自动分页和手动分页。默认避免把段落标题单独留在页底，歌词、和弦与简谱尽量作为一个单元分页。超出一页时生成多页，不无限缩小字体。

PDF 是固定布局文件，不能当作可编辑工程备份。正式方案优先保证中文字体与输出一致性；是否使用矢量文字及字体嵌入，需要在实现时核验移动端浏览器能力与所选导出方案。

## 8. 保存与轻量实现

优先使用本地网页：曲库保存在当前设备和浏览器；谱子识别由用户选择的外部 AI 完成；不在程序中内置识图模型。

必须包含自动保存状态、保存失败提示、关闭后恢复、单曲工程导出与整库备份/恢复。无账号的本地存储不等于多设备同步，浏览器清理也可能删除数据。首版通过导入导出在设备间转移；以后确有需求再做账号或云同步。

离线访问/添加到主屏幕作为后续增强，需要在实际浏览器和部署环境验证，不能仅凭有一个 HTML 文件就保证可用。

## 9. 分阶段实施与验收

### 第一轮：可靠制谱闭环

核验并复用已有代码，完善手机/平板布局、A4 排版、和弦/级数切换、歌词编辑、AI 和弦歌词导入、PDF/PNG/工程导出、自动保存、文件夹/收藏/搜索。

验收：原创样例从 AI 文本导入后，曲名、和弦、歌词、段落不丢；编辑后重开仍在；和弦与级数来回切换不改音高；导出打印与 A4 预览一致；旧工程可导入；失败导入不覆盖已有内容。

### 第二轮：简谱与试听

扩展独立拍点数据、旋律简谱编辑、歌词锚点、和弦播放、节拍器、旋律播放和段落循环；校验变调夹、转调与实际发声的一致性。

验收：能正确处理一字多音、休止、跨小节连音、八分音符、缺失节奏、弱起；没有旋律时不自动编造旋律；未知项不会被悄悄当成确定值。

### 第三轮：排练和管理增强

演出曲单、自定义排序、标签筛选、演出阅读、离线缓存、备份恢复体验与更丰富的版式模板。

每阶段先完成真实用例，再扩大范围；上面阶段顺序不意味着后续需求被删除。

## 10. 建议确认的方向

1. 默认采用暖纸白 + 浅绿色，平板大谱面，手机底部操作栏。
2. AI 主导入采用固定小型 JSON 代码块，乐谱正文优先复用 ChordPro / Sparks NMN 等现成格式，并接受标准格式原文。
3. 基于现有工作台核验后升级，先完成可靠的制谱与导出闭环，再补完整简谱与试听。
