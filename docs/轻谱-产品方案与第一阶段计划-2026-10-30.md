# 轻谱产品方案与第一阶段计划

记录日期：2026-10-30  
来源：外部 AI 产品评审意见 + 当前项目实现复核  
说明：本记录用于后续产品决策。涉及模型识谱准确率、竞品现状和开源库最新能力的结论，后续要用自己的测试谱集和实际设备复核。

## 一句话定位

轻谱把中文流行歌的图片谱变成可以修改、校正、播放、排练、导出和现场使用的功能谱。

## 产品初心

很多乐手手里的谱子来自图片、截图或 PDF。它们能看，但难以修改；歌词、和弦和简谱容易错位；变调夹、调号、拍号和速度经常不完整；到了现场还要在不同应用之间切换，翻页和临时改谱都不方便。

轻谱的目标不是做一个功能最多的完整制谱软件，而是把一张静态谱快速变成一份真正属于用户、可以继续修改和现场使用的谱。

产品采用轻量路线：外部多模态 AI 负责看谱图和转写，轻谱负责固定格式解析、自动修正、结构校验、歌词与简谱对齐、排版、播放和导出。这样可以复用豆包、GPT、Claude 等现有能力，也避免在网页里重复开发图片识谱模型。

## 首要服务对象

第一目标用户是自弹自唱的吉他手。他们最容易完整使用“图片谱 → AI 识别 → 手动校正 → 改调 / 练习 → 现场看谱”的闭环。

第二目标用户是乐队排练和现场乐手。贝斯手、键盘手和其他乐手可以复用和弦、级数、歌词、曲库和演出模式，不单独增加复杂入口。

## 核心差异

轻谱应该占住这一组组合能力：

- 中文流行歌曲
- 图片谱导入
- 和弦、数字级数和罗马数字
- 歌词逐字对应
- 可选简谱旋律
- 手机 / 平板现场看谱
- A4 输出
- 不确定内容可定位、可手动修正

这让轻谱和 Guitar Pro、Ultimate Guitar、OnSong、forScore、iReal Pro 形成不同侧重点：轻谱重点解决中文图片谱到可编辑功能谱的转换，以及和弦、歌词、简谱三者的校正关系。

## 已有产品能力

### 谱库和写谱

- 默认进入谱库，底部保留“谱库 / 写谱”两个入口。
- 谱库支持搜索、收藏、文件夹、标签、排序、演出曲单和回收站。
- 打开歌曲可以直接进入看谱 / 演出。
- 写谱页面编辑歌曲信息、段落、小节、和弦、歌词、简谱和排版。
- 新建歌曲从空白开始，不强行预填歌名、作者、调号、速度或示例段落。

### AI 智能导入

- 复制统一提示词，把谱图交给外部 AI。
- 支持 JSON、JSON5 风格 JSON、代码围栏、多个 JSON、多个代码块、前后说明文字、工程 JSON、ChordPro、ChordMark 和 ABC。
- 自动处理注释、尾逗号、单引号、反引号、中文引号、未加引号的键名、Python 布尔值、外层 data / result / output 包装和常见字段别名。
- 支持多页连续小节编号、逐字歌词对应、简谱音符对应、反复记号、第一 / 第二结尾和问题列表。
- 语法可以自动修正，音乐内容仍要通过严格校验和用户核对。
- 支持追加到当前歌曲，检查歌名、调号、拍号、变调夹和下一小节编号。

### 编辑和校正

- 编辑歌名、作者、调号、调式、变调夹、拍号、BPM、段落、小节、和弦和时值。
- 支持斜杠和弦、和弦名、数字级数、罗马数字和双行显示。
- 歌词可逐字移动、改字号、改对应音符、改坐标、拆字、删除、跨小节移动和自由放置。
- 简谱音高、时值和显示状态可以单独修改。
- 支持重复起点、重复终点、重复次数、第一结尾、第二结尾和小节编号。
- 有撤销、重做和自动保存。

### 和弦图和开源资源

- 复用 SVGuitar 和 chords-db。
- 支持和弦搜索、多把位、斜杠和弦、和弦图尺寸、排序、删除、批量配图和 SVG 导出。
- 复用 Tonal、ChordMark、ABCJS、JianpuRender、Tone.js、Lucide、html-to-image、jsPDF 和 Vite。
- 继续坚持优先使用成熟开源库，避免重复造轮子。

### 练习、演出和输出

- Tone.js 播放和弦、旋律、节拍器、循环、长音、分解和扫弦伴奏。
- 演出支持手动翻谱、按页翻谱、缓慢跟随、提前倒数、视觉节拍、静音视觉节拍、颜色和强度设置。
- 支持 A4 PDF、逐页 PNG、浏览器打印、工程 JSON、整库备份 JSON、ChordPro 和 ABC。
- 支持浅绿、纸黄、白蓝、黑白、纯白主题，以及无衬线、衬线、等宽字体。

## 外部评审提出的主要建议

### 图片谱校正

1. 导入时保留原图或裁剪后的小节图，校正时可以和识别结果并排对照。
2. 图片最好按一行或 4–8 小节裁剪并编号，降低 AI 识别错误率。
3. 导入后显示问题列表，拍数、歌词字数、音符数量、和弦、编号和 AI 标记的不确定位置都可以点击定位。
4. 将来的局部修复可以只重新识别一个小节，不需要整首歌重新导入。

### AI 格式和可靠性

1. 内部继续使用 JSON，保留版本号和固定外层结构。
2. 可以支持每小节局部解析或 JSONL 思路，使单个坏小节不会阻塞整首歌。
3. 提示词必须有完整输入输出示例、版本号、拍数自检和“不确定就写 ?、不要猜”的要求。
4. 建立约 20 首真实测试谱集，记录不同模型、不同版本和不同谱型的错误率。
5. 识谱提示词应分阶段：先识别结构和元信息，再识别小节内容。

### 校正模式和编配模式

这是未来六线谱扩展时的重要概念：

- 校正模式：保持原谱弦号 / 品位或原始位置，修正 AI 识别错误。
- 编配模式：保持音高不变，重新寻找其他弦和把位。

当前功能谱先采用简化版本：校正歌词、简谱、和弦和小节关系；以后加入六线谱时再扩展弦、品、调弦、技巧和音高模型。

### 演出稳定性

外部评审认为演出模式当前更需要稳定性，而不是继续增加视觉功能。优先建议：

- 演出锁，防止误触编辑和缩放。
- 生产环境完整离线缓存。
- 蓝牙翻页踏板和键盘方向键支持。
- 手动翻页优先，自动翻页默认谨慎开放。
- 禁止下拉刷新和误触离开。
- 曲单中快速进入下一首。
- 下一页预览。

### 延后到后续阶段的扩展

- alphaTab、Guitar Pro、MusicXML 和六线谱 / 五线谱只读导入。
- 六线谱轻量编辑和换把位。
- 多声部和复杂演奏技巧。
- 云同步、账号、多设备同步和多人协作。

这些方向有价值，但会显著扩大数据模型和交互复杂度，不放在第一阶段。

## 第一阶段实施计划

### P0：原图对照

- 智能导入面板支持选择一张或多张谱图作为参考。
- 导入时显示缩略图和文件顺序。
- 成功导入后，在当前歌曲里保留本次会话的原图参考入口。
- 点击小节问题时，优先显示对应参考图。

第一阶段先用当前页面会话保存参考图，避免把大图片直接写进 localStorage。后续再评估 IndexedDB 持久化。

### P0：可定位的问题列表

- 识谱结果中的问题以按钮形式显示。
- 位置包含小节编号时，可以直接选中并滚动到对应小节。
- 问题列表区分自动修正、AI 待确认、拍数问题、歌词 / 音符对应问题和结构问题。
- “已核对完成”仍然保留，但不能替用户修改音乐内容。

### P0：演出锁

- 进入演出模式后提供“演出锁”。
- 锁定后隐藏编辑、主题、更多功能和底部导航的交互。
- 翻页、播放和解锁按钮仍可用。
- 解锁使用明确按钮，后续可增加长按 2 秒解锁。

### P0：生产环境离线缓存

- 使用 Service Worker 缓存应用壳、脚本、样式、图标和已访问资源。
- 网络断开时优先读取缓存。
- 版本升级时清理旧缓存并使用新的缓存版本号。
- 开发环境不注册 Service Worker，避免本地开发被旧缓存干扰。

### P1：局部修复和测试谱集

- 允许只替换某个小节的识别结果。
- 记录图片编号、小节编号和解析结果之间的来源关系。
- 建立真实测试谱集，记录拍数、歌词、简谱、和弦、重复记号和位置错误。

### P1：现场硬件操作

- 监听键盘方向键、PageUp / PageDown。
- 验证常见蓝牙翻页踏板。
- 增加 Tap Tempo。
- 增加曲单下一首 / 上一首快捷操作。

## 当前产品边界

- 图片识别由外部 AI 完成，轻谱负责解析和修订。
- ABC 以单声部旋律为主。
- 复杂嵌套反复、D.S. / D.C.、多声部和中途变调 / 变拍需要拆分或核对。
- 小调能力仍不完整。
- 当前没有账号、云同步、多人协作和完整离线缓存。
- PDF 主要是排版图片页，暂不保证文字搜索。
- 练习节奏下的自动翻谱属于估算，不能等同原谱演奏节奏。

## 产品决策原则

1. 先服务真实自弹自唱和现场使用，再扩展专业制谱能力。
2. 先保证导入可发现错误、现场不误触、数据可备份，再增加复杂功能。
3. JSON 作为内部歌曲数据和 AI 外壳格式继续保留，兼容 ChordPro / ABC 等外部格式。
4. 语法错误可以自动修正，音乐语义不确定时必须标记并交给用户确认。
5. 屏幕、编辑、演出、PDF 和 PNG 必须尽量共用同一份歌曲数据和排版规则。
6. 能复用成熟开源库就不重复开发；引入新库前核查许可证、体积和移动端表现。
7. 现场模式优先可靠和低误触，视觉效果默认克制。

## 如果只能继续做三件事

1. 原图与解析谱面对照校正。
2. 可点击、可定位的问题列表和局部小节修复。
3. 演出锁、离线缓存和翻页稳定性。
