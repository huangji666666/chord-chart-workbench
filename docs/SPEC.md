## 1. 定位与范围边界

### 1.1 定位

功能谱（lead sheet / chord chart）以**和弦或和声级数、段落、小节、时值和演奏提示**为核心。
它面向乐手排练和现场演出，使用者主要在手机和平板上编辑。

**它不是**五线谱编辑器，**也不是**旋律简谱软件。旋律不在数据模型里。

### 1.2 本版包含

| 项 | 说明 |
| --- | --- |
| 歌曲信息 | 标题、艺人、备注、调号、BPM、拍号、风格 / 效果器预设 |
| 段落 | 名称、重复次数（演奏标注）、演奏提示、有序小节 |
| 小节 | 类型（含事件 / 空白）、有序事件 |
| 事件 | 和弦、休止 |
| 和弦 | 根音 + 升降号、性质、可选斜杠低音、时值 |
| 显示 | 和弦名称显示、数字级数显示 |
| 存储 | 浏览器 localStorage、JSON 工程文件导入导出 |
| 导出 | 浏览器打印 / 保存为 PDF、高清 PNG、演出阅读模式 |

### 1.3 本版明确不包含

这些**不是**「还没做好」，而是本版有意不做。实现不得伪装成已经支持：

- 五线谱、简谱旋律编辑与播放。
- 音频播放、音频识别和弦。
- 任何需要外部模型服务的 AI 功能。
- 服务器、数据库、账号、云同步。第一版免登录，数据只存在当前浏览器。
- **实际移调。** 显示方式切换（和弦名 ↔ 级数）不是移调，不得冒充移调。
- **小调与复杂理论拼写。** 未实现时给出明确提示，绝不输出可能错误的结果。
- 扩展和弦（add9 / 9 / 11 / 13 / 6 / m7b5 / alt 等）、变化音、省略音。
- 自动复制小节来表达「重复次数」。`repeat` 只是演奏标注。

### 1.4 术语

| 术语 | 含义 |
| --- | --- |
| 拍（beat） | 时值的统一单位。1 拍等于拍号分母所表示的音符（见 §3.1）。 |
| 小节（bar） | 一个计量单位，应容纳 `beatsPerBar` 拍。 |
| 段落（section） | 一组连续小节，带名称（Intro / Verse / Chorus …）。 |
| 事件（event） | 小节里的一个音乐单位，目前是和弦或休止。 |
| 空白小节（empty bar） | 整小节留白，**没有事件**。与休止不是一回事。 |
| 功能谱文本 | 用户输入的 `[段落]` + 和弦列表文本，语法见 §4。 |

## 2. 数据模型

### 2.1 结构总览

```
Song
├── schemaVersion, id, createdAt, updatedAt
├── title, artist, notes
├── key { tonic, mode }
├── bpm, timeSignature, style
├── layout { barsPerRow, displayLines[], dimSuffix, fontScale,
│            chordSymbols, accidentalGlyphs, seventhSuffix, restText }
└── sections: Section[]
    ├── id, name, repeat, cue
    └── bars: Bar[]
        ├── id, type
        ├── lyrics: Array<{ text } | null>   ← 可缺省，按事件下标对齐（§8.9）
        ├── textBlocks: TextBlock[]          ← 可缺省，自由定位的文字块（§8.10）
        └── events: (ChordEvent | RestEvent)[]
            ├── ChordEvent { id, beats, chord { root, quality, bass } }
            └── RestEvent  { id, beats }

TextBlock { id, text, x, y, anchor }
```

JSDoc 类型定义在 `src/core/song.js` 与 `src/core/chord.js`，那是代码层面的权威版本。

### 2.2 字段说明

**Song**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `schemaVersion` | number | 必须等于 1。 |
| `id` | string | 以 `sng_` 开头，全局唯一。 |
| `createdAt` / `updatedAt` | string | ISO 8601。任何写操作都要刷新 `updatedAt`。 |
| `title` | string | 非空，≤ 120 字符。 |
| `artist` | string | ≤ 120 字符。 |
| `notes` | string | ≤ 500 字符。 |
| `key` | object | `{ tonic: 音名, mode: 'major' }`。`mode` 只接受 `'major'`。 |
| `bpm` | number | 整数，20–400。 |
| `timeSignature` | string | `'4/4'` \| `'3/4'` \| `'6/8'`。 |
| `style` | string | 风格或效果器预设名，≤ 120 字符。 |
| `sections` | Section[] | ≤ 200 段。 |
| `layout` | object | 见下。 |

> 关于「艺人或备注」：需求里写的是「艺人或备注」一个位置，实现上拆成了 `artist` 和
> `notes` 两个字段 —— 谱面需要单独显示备注（§8.1），混在一个字段里没法可靠地分开渲染。
> 如果后续确认只要一个字段，改动很小。

**LayoutSettings**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `barsPerRow` | number | 只能是 `2` \| `4` \| `8`。 |
| `displayLines` | string[] | 1–3 项，取值 `'chord'` \| `'degree'` \| `'roman'`，不重复。只影响显示，不改数据（§6.4、§8.1.1）。 |
| `dimSuffix` | string | **可缺省**，取值 `'dim'` \| `'°'`。缺省等价于 `'dim'`。只影响级数行里减三和弦的后缀写法（§6.7.1），不改数据。 |
| `chordSymbols` | string | **可缺省**，取值 `'common'` \| `'jazz'`。缺省等价于 `'common'`。和弦性质后缀用哪套符号体系（§5.1.1），只影响显示与文本导出，不改数据。 |
| `accidentalGlyphs` | string | **可缺省**，取值 `'glyph'` \| `'ascii'`。缺省等价于 `'glyph'`。升降号画成 `♯` `♭` 还是 `#` `b`（§5.1.2）。**只作用于和弦名与音名，不作用于级数行。** |
| `seventhSuffix` | string | **可缺省**，取值 `'subscript'` \| `'plain'` \| `'superscript'` \| `'parens'`。缺省等价于 `'subscript'`。属七和弦在级数行里后缀 `7` 的位置（§6.6）。 |
| `restText` | string | **可缺省**，取值 `'cn'` \| `'dash'` \| `'R'`。缺省等价于 `'cn'`。休止符在谱面上的文字（§8.1.2）。 |
| `fontScale` | number | 0.8–1.6，基准 1。 |

> **`layout` 里的显示偏好字段一律「缺省即旧行为」。** `dimSuffix` / `chordSymbols` /
> `accidentalGlyphs` / `seventhSuffix` / `restText` 五个字段都是**可缺省**的：
> 缺失时取上表列的缺省值，而那个值**必须**等于引入该字段之前的观感。
> 这不是风格问题 —— `library.js` 读 `localStorage` 时**直接调 `validateSongShape`、不走迁移**，
> 字段一旦设成必需，用户已存的每一首歌都会在下次打开时被判为损坏并隔离（§7.4）。

**Section**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | string | 以 `sec_` 开头，唯一。 |
| `name` | string | 非空，≤ 40 字符。允许同名段落。 |
| `repeat` | number | 整数 1–99。**只是演奏标注**，不复制小节。 |
| `cue` | string | 演奏提示，≤ 200 字符，可为空。 |
| `bars` | Bar[] | ≤ 512 小节。 |

**Bar**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | string | 以 `bar_` 开头，唯一。 |
| `type` | string | `'chords'` \| `'empty'`。 |
| `events` | SongEvent[] | ≤ 32 个。`type === 'empty'` 时**必须为空数组**。 |
| `lyrics` | Array<{ text } \| null> | **可缺省**。按**事件下标**对齐：`lyrics[i]` 对应 `events[i]`（§8.9）。缺失或整段为空即等于「没有歌词」（旧行为）。`type === 'empty'` 时无意义，应忽略。 |
| `textBlocks` | TextBlock[] | **可缺省**。自由定位的文字块（§8.10）。缺失或为空数组即等于「没有文字块」（旧行为）。`type === 'empty'` 时仍可存在（空白小节也能写文字，如「间奏」）。 |

**TextBlock**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | string | 以 `txt_` 开头，全局唯一。 |
| `text` | string | 文字内容，可含 `\n` 换行（逐行写），≤ 500 字符。空串的块不落盘。 |
| `x` | number | 相对小节框**左边**的水平位置，0–1（0 = 贴左，1 = 贴右，0.5 = 居中）。 |
| `y` | number | 相对小节框**顶部**的垂直位置，0–1（0 = 贴顶，1 = 贴底）。 |
| `anchor` | number | 对齐到的**和弦下标**（`bar.events[anchor]`），`-1` 表示小节级（不跟某个和弦）。文字块跟着和弦走：和弦删了 / 移动，文字块随之调整（§8.10）。 |

**SongEvent**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | string | 以 `evt_` 开头，唯一。 |
| `kind` | string | `'chord'` \| `'rest'`。 |
| `beats` | number | 有限正数，> 0 且 ≤ 64。单位是拍。 |
| `chord` | object | 仅 `kind === 'chord'` 时存在；`kind === 'rest'` 时不允许出现该字段。 |

**Chord**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `root` | string | 音名：`A`–`G` 开头，后跟 0–2 个同向升降号。例如 `C`、`F#`、`Bb`、`E##`。 |
| `quality` | string | 九种之一，见 §5.1。 |
| `bass` | string \| null | 斜杠低音音名，格式同 `root`；无斜杠低音时为 `null`。 |

音名里的升降号**只用 ASCII 的 `#` 和 `b` 存储**，显示时才换成 `♯` / `♭`。
输入时 `♯` / `♭` 也会被接受并规范化。

### 2.3 关键约束

1. **ID 不能用数组下标代替。** 复制、上下移动、删除元素之后，ID 必须依然稳定唯一。
   校验器会对整棵对象树查重，出现重复 ID 直接判为非法。
2. **数据必须能序列化为 JSON。** 不存 `undefined`、函数、Date 对象、Map、循环引用。
   时间统一用 ISO 8601 字符串。
3. **时值使用统一且明确的数值单位** ——「拍」，见 §3。字段名就叫 `beats`，避免单位歧义。
4. **单一数据源。** 文本输入、触屏编辑、谱面预览、导出全部读写同一份 `Song` 对象。
   不允许几个界面各自维护一份互相不一致的歌曲。
5. **渲染出来的 DOM 不是歌曲源数据。** 任何从 HTML 反推数据的做法都是错的。
6. **`repeat` 先作为演奏标注**，不自动复制实际小节。

### 2.4 空白小节 ≠ 休止

这是两条完全不同的音乐含义，必须在数据和界面上都分清楚：

| | 空白小节 | 休止 |
| --- | --- | --- |
| 数据表达 | `bar.type = 'empty'`，`events = []` | `bar.type = 'chords'`，含 `kind: 'rest'` 的事件 |
| 含义 | 这一小节不写任何内容（还没排、留白、交给别人发挥） | 明确要求这几拍**不发声** |
| 谱面 | 保留正常小节宽度，内部留白 | 画出休止标记和时值 |
| 文本语法 | 单独一个 `0` | `R:2` |
| 混用 | 不允许：空白小节不能携带任何事件 | 允许和和弦同处一个小节（如 `C:2 R:2`） |

**`0` 是空白小节的专用记号，不能借去表示休止。** 简谱里 `0` 确实是休止符，但本工具的
文本语法已经把 `0` 用给了空白小节 —— 同一个字形在这里必须只有一个意思。
所以 `layout.restText`（§8.1.2）的可选值里**没有** `'0'`，这是刻意的，不是漏了。

## 3. 时值与拍号规则

### 3.1 拍的单位定义

**1 拍 = 拍号分母所表示的音符。** 这是全应用唯一的时值单位。

| 拍号 | 1 拍 = | 每小节拍数 `beatsPerBar` | 界面提示 |
| --- | --- | --- | --- |
| `4/4` | 四分音符 | 4 | 四分音符 = 1 拍，每小节 4 拍 |
| `3/4` | 四分音符 | 3 | 四分音符 = 1 拍，每小节 3 拍 |
| `6/8` | **八分音符** | 6 | 八分音符 = 1 拍，每小节 6 拍 |

> **6/8 必须给出提示。** 在 6/8 里 1 拍是八分音符，而乐手口语上的「一大拍」通常是附点四分音符
> （= 3 拍）。输入界面必须明确写出这个单位，否则 `C:2` 到底是指两个八分音符还是两个大拍会
> 造成误读。本版统一按八分音符计，界面上写清楚。

### 3.2 小节长度

每个小节应该正好容纳 `beatsPerBar` 拍。空白小节视为满足（不参与计算）。

### 3.3 时值校验规则

对每个小节，按以下三种情况处理：

| 情况 | 规则 | 失败时 |
| --- | --- | --- |
| **A. 全部省略时值** | 把整小节拍数平均分成 n 份，每份 `beatsPerBar / n` 拍 | 无法精确表达（§3.4）→ 报错，**不四舍五入** |
| **B. 全部写明时值** | 校验 Σ 时值 = `beatsPerBar`（容差 1e-9） | 欠拍 / 超拍 → 报错，定位到段落和小节 |
| **C. 明确与省略混合** | **直接报错**，提示补全时值 | 不做任何推测 |

补充规则：

- 时值必须是**正数**。`0` 和负数一律拒绝。
- 时值上限 64 拍。
- 浮点数一律用容差 `1e-9` 比较，不允许 `===`。
- 小节里一个事件都没有，且类型是 `'chords'` → 报错：「这一小节没有任何事件。如果要留白，请把小节设为空白小节（`0`）」。

**为什么混合情况直接报错？** 因为「两个写明时值的和弦 + 一个没写的和弦」有太多合理解释：
补满剩余、平分剩余、还是作者漏写了？猜错会安静地产生一份错的谱子，比报错危险得多。

### 3.4 「精确可表达」的判定

均分得到的时值 `r = beatsPerBar / n`，判定标准：

```
r × 16 必须是整数
```

也就是要求时值最多精确到 **1/16 拍**（在 4/4 里相当于 64 分音符）。判定用容差 1e-9。

| 拍号 | n | r | 结果 |
| --- | --- | --- | --- |
| 4/4 | 2 | 2 | ✅ |
| 4/4 | 4 | 1 | ✅ |
| 4/4 | 3 | 1.333… | ❌ 报错，要求填写时值 |
| 3/4 | 2 | 1.5 | ✅（附点四分音符） |
| 6/8 | 4 | 1.5 | ✅ |
| 6/8 | 5 | 1.2 | ❌ 报错 |

不允许把 1.333… 悄悄变成 1 或 1.5 —— 那会改变音乐内容。

### 3.5 修改拍号

改拍号之后必须**重新校验**，但**不得静默改写已有时值**。
欠拍 / 超拍的小节由用户决定怎么改（补一个和弦、改时值、或删掉一节）。

## 4. 输入语法

### 4.1 概览

```
[Intro]
C:4 | Am:4 | F:2 G:2 | C:4

[Verse]
C:2 G/B:2 | Am7:4 | F:2 G:2 | 0
```

### 4.2 语法元素

| 写法 | 含义 |
| --- | --- |
| `[名称]` | 开始一个新段落。必须单独成行（允许前后空白）。 |
| `\|` | 小节分隔符。 |
| 换行 | **也是小节分隔符**（见 §4.3）。 |
| `C:4` | 和弦 + 时值。时值单位是拍。 |
| `C` | 和弦，时值省略 → 参与自动分配（§3.3 情况 A / C）。 |
| `G/B` | 斜杠和弦。 |
| `0` | 一个完整的**空白小节**。 |
| `R:2` | 休止 2 拍。`R` 也可以省略时值。 |

一个小节内部，多个事件用**空白字符**分隔：`C:2 G/B:2` 是一个小节里的两个和弦。

### 4.3 换行规则（重要）

**一个换行等价于一个 `|`。** 也就是说：

- 换行**不会**被当作可忽略的空白。这一点是刻意的：如果把换行当空白，
  下面这种写法就会把两个本来独立的小节悄悄合并成一个小节。

  ```
  [Verse]
  C:4        ← 第 1 小节
  Am:4       ← 第 2 小节
  ```
  按本规则解析成 2 个小节；若把换行当空白，会解析成「一个小节里放着 C:4 和 Am:4」，
  这是一个安静的数据损坏，必须避免。

- 想在一行里写多个小节，就用 `|`：`C:4 | Am:4`。
- **行尾多余的 `|` 允许出现并被忽略**：`C:4 | Am:4 |` 解析为 2 个小节。
- **连续分隔符（空片段）报错**：`C:4 || Am:4` → 报错，提示「空小节片段；整小节留白请写 `0`」。
  因为忽略空片段会把作者手误静默吞掉，报错更安全。
- **完全空白的行被忽略**，可用来分隔段落、方便阅读。
- 只想写一个空白小节，就写 `0`。

### 4.4 段落规则

- `[名称]` 之后的所有小节都归属于该段落，直到下一个 `[...]`。
- 段落名去掉首尾空白后不能为空（`[]` 或 `[   ]` 报错）。
- 段落名内部允许空格和中文：`[副歌 第二次]`。
- 允许出现同名段落（两段 `[Chorus]` 是合法的，也是常见的）。
- **第一个 `[...]` 之前出现任何内容都报错**，提示「内容不属于任何段落，请先写段落名」。
  不做自动补一个默认段落的猜测。

### 4.5 时值省略

| 小节内的情况 | 行为 |
| --- | --- |
| 全部省略 | 平均分配整小节拍数（§3.3 A） |
| 全部写明 | 校验总和（§3.3 B） |
| 混合 | 报错，要求补全（§3.3 C） |

### 4.6 错误定位

解析错误必须能定位到具体位置，并**保留用户的原始草稿**。

错误的展示格式：

```
第 3 行 · 第 2 小节 · 第 1 个事件：时值必须是正数
```

错误对象至少包含：`line`、`column`、`sectionName`、`barIndex`（该段落内第几小节）、
`eventIndex`（该小节内第几个事件）、`code`、`message`。

错误码（已实现，定义在 `src/core/parser.js` 的 `PARSE_CODES`；时值类错误码
定义在 `src/core/duration.js` 的 `DURATION_CODES`）：

| code | 触发条件 |
| --- | --- |
| `E_SECTION_NAME_EMPTY` | `[]` 或 `[  ]` |
| `E_CONTENT_BEFORE_SECTION` | 第一个段落头之前有内容 |
| `E_BAR_SEGMENT_EMPTY` | 出现连续分隔符，产生空片段 |
| `E_CHORD_BAD_ROOT` | 根音不是 A–G 开头 |
| `E_CHORD_UNKNOWN_QUALITY` | 后缀不是支持的九种之一 |
| `E_BASS_INVALID` | 斜杠低音音名非法 |
| `E_DURATION_INVALID` | 时值不是正数 / 不是数值 / 超过上限 |
| `E_DURATION_MIXED` | 同一小节里既有写明又有省略的时值 |
| `E_DURATION_UNDER` | 小节欠拍 |
| `E_DURATION_OVER` | 小节超拍 |
| `E_DURATION_NOT_DIVISIBLE` | 均分结果无法精确表达 |
| `E_ZERO_WITH_DURATION` | 写成 `0:2` 之类 |
| `E_BAR_HAS_NO_EVENT` | `chords` 类型小节里没有任何事件 |

### 4.7 解析与应用的原子性

- 用户输入文本先作为**草稿**，校验全部通过后才整体应用到歌曲数据。
- **解析失败不得破坏已有歌曲。** 失败时保留原始草稿并显示错误位置。
- 段落的 `repeat` 和 `cue` 不在文本语法里，只能通过界面编辑。

### 4.8 文本导出的符号

文本导出（`songToText`）用的是**一套独立的、固定的记号**，与谱面风格只有一处关联：

| 元素 | 导出成 | 是否跟随谱面设置 |
| --- | --- | --- |
| 和弦性质后缀 | 按 `layout.chordSymbols`（§5.1.1） | **跟随** |
| 升 / 降号 | ASCII `#` / `b` | **不跟随** `accidentalGlyphs` |
| 休止 | `R` | **不跟随** `restText` |
| 空白小节 | `0` | 不适用（文本语法的记号） |
| 时值 | 显式数字（`C:4`） | 不适用 |

**为什么只有性质后缀跟随。** 升 / 降号、`R`、`0` 是这套文本语法的**记号**
（§4.2 的定义表），它们不是「怎么写好看」的问题，而是「这句话读不读得懂」的问题 ——
把 `R` 换成 `—` 就不再是同一套语法了。而和弦性质后缀是**内容**，
换一套符号体系不影响语法的可解析性（§5.2.1 保证别名都能读回来）。

**缺省下与旧行为逐字相同**：`chordSymbols: 'common'` 时导出的就是 `Cmaj7` / `C#m7` /
`R:2` / `0`，与引入这个开关之前一模一样。

**这条打破了原先「文本导出不受任何显示偏好影响」的约定**，是有意为之：
既然输入放开了（§5.2.1），导出再死守通用写法，就会出现「打 `CΔ7` 存下来、
导出变 `Cmaj7`」而用户不知道为什么。现在的规则更好解释：
**屏幕上怎么写，导出的文本就怎么写；但语法记号永远不跟着变。**

## 5. 和弦

### 5.1 支持的和弦性质

「后缀写法」一列是**显示**用的字形，由 `layout.chordSymbols` 选一套（§5.1.1）。
**解析**接受的范围比这更宽 —— 两套符号体系加上常见别名都能读进来（§5.2.1）。

| id | `common` 后缀 | `jazz` 后缀 | 含义 | 示例（`common` / `jazz`） |
| --- | --- | --- | --- | --- |
| `maj` | 不写后缀 | 不写后缀 | 大三和弦 | `C` / `C` |
| `m` | `m` | `-` | 小三和弦 | `Cm` / `C-` |
| `7` | `7` | `7` | 属七和弦 | `C7` / `C7` |
| `maj7` | `maj7` | `Δ7` | 大七和弦 | `Cmaj7` / `CΔ7` |
| `m7` | `m7` | `-7` | 小七和弦 | `Cm7` / `C-7` |
| `sus2` | `sus2` | `sus2` | 挂二和弦 | `Csus2` / `Csus2` |
| `sus4` | `sus4` | `sus4` | 挂四和弦 | `Csus4` / `Csus4` |
| `dim` | `dim` | `°` | 减三和弦 | `Cdim` / `C°` |
| `aug` | `aug` | `+` | 增三和弦 | `Caug` / `C+` |

只有三处不同（`m` `maj7` `m7` `dim` `aug`），**和弦种类一个没变** —— 换的是「怎么写」，
不是「支持哪些和弦」。扩展音 `9 / 11 / 13`、半减七 `ø`、六和弦仍然不在表里（§5.4）。

#### 5.1.1 和弦性质符号体系（`chordSymbols`）

两种都在用，所以做成设置项，由 `layout.chordSymbols` 决定：

| 取值 | 说法 | 示例 |
| --- | --- | --- |
| `'common'`（缺省） | 通用写法，字母后缀 | `Cmaj7` `Cm7` `Cm` `Cdim` `Caug` |
| `'jazz'` | 爵士圈写法，符号后缀 | `CΔ7` `C-7` `C-` `C°` `C+` |

- **缺省 `'common'` 等于旧行为**，老谱子观感不变。
- **只影响和弦名与文本导出。** 级数行有自己的后缀规则（罗马字形下 `m` 被小写吸收、
  减三后缀由 `dimSuffix` 单独管），**不跟随这个开关** —— 两套规则叠在一起会打架。
- **`dim` 这一格与 §6.7.1 的 `dimSuffix` 是两件事，别混。** `chordSymbols` 管的是
  **和弦名**里的性质符号（`Cdim` → `C°`）；`dimSuffix` 管的是**级数行**的后缀
  （`7dim` → `7°`）。两个开关互不影响：可以把和弦名设成 `C°` 而级数行仍旧写 `7dim`。

#### 5.1.2 升降号字形（`accidentalGlyphs`）

| 取值 | 谱面 |
| --- | --- |
| `'glyph'`（缺省） | `F♯m` `B♭maj7` |
| `'ascii'` | `F#m` `Bbmaj7` |

- 存储格式**永远是 ASCII**（§2.2）：音名在数据里只写 `#` / `b`，字形是渲染时才换的。
- **只作用于和弦名与音名。级数行不受影响** —— `#4` / `b7` 里的 `#` `b` 是**级数限定符**，
  属于级数记法本身（§6.1），不是音名升降号。改它会让所有已有谱子的级数行外观都变。
  这是刻意的划界：缺省值必须等于旧行为，而旧行为下这两处本来就不一样。
- 文本导出始终用 ASCII（§4.8），与本开关无关。

### 5.2 解析规则

- 后缀匹配**区分大小写**，且**最长后缀优先**（否则 `maj7` 会被 `m` 抢先吃掉）。
- 根音音名大小写不敏感，内部统一成大写：`c#m7` 等价于 `C#m7`。
- 升降号允许 `#`、`b`、`♯`、`♭`，最多两个且必须同向（`##` 可以，`#b` 报错）。
- 斜杠低音必须写完整音名，只能有一个斜杠。

#### 5.2.1 输入别名（决策点 H：放开输入）

**规则：屏幕上能显示的写法，输入框里就必须能打进来。** 否则会出现「看着一个、
打着一个」的别扭状态 —— 而且用户会以为自己打错了。

解析层接受下面全部写法，**统一规范化成同一个性质 id**。数据里永远只存 id，
不存在「用户打的是哪种写法」这个信息（§6.4 的同一条原则）。

| 打进来的写法 | 规范化成 |
| --- | --- |
| `m`、`min`、`-` | `m` |
| `maj7`、`M7`、`Maj7`、`MAJ7`、`Δ`、`Δ7` | `maj7` |
| `m7`、`min7`、`-7` | `m7` |
| `M`（单独一个） | `maj` |
| `dim`、`°`、`o` | `dim` |
| `aug`、`+` | `aug` |
| `sus2`、`sus4`、`7`、`maj`（不写后缀） | 原样 |

之所以现在才放开：选项越多，两两组合的验证量按平方增长（§11 第 9 条）。
这一轮放开的理由是**输入是显示的逆运算**，两边不成对才是真的缺陷。

> **放开的是「怎么写」，不是「支持哪些和弦」。** 半减七 `ø` / `m7b5`、
> 扩展音 `9` `11` `13` `add9`、六和弦 `6` `m6`、强力和弦 `5`、挂留七 `7sus4`、
> 小大七 `mmaj7`、变化音 `alt` / `no3` —— **一个都没加**，照旧明确报错（§5.4）。
> 这两件事必须分开：前者是字形问题，后者是乐理范围问题。

> **往返会「变形」，这是有意接受的。** 打 `CΔ7` 存进数据是 `{root:'C', quality:'maj7'}`，
> 导出时写成什么由当前 `chordSymbols` 决定（§4.8）—— 选 `common` 就写回 `Cmaj7`。
> 也就是「打进去的字不一定原样吐出来，但音乐事实永远不变」。
> 这条必须明说，不能让人以为「我打什么就一定存什么」。

### 5.3 斜杠低音

`G/B` = 根音 `G`、性质 `maj`、低音 `B`。低音同样允许升降号（`C/Eb`）。

### 5.4 不支持的写法

**必须报错并说明，绝不伪装成已经正确解析。** 针对性提示：

| 写法 | 提示 |
| --- | --- |
| `m7b5`、`ø`、`m(b5)` | 半减七和弦本版不支持，请改用 dim |
| `add9`、`9`、`11`、`13` | 扩展音本版不支持 |
| `6`、`m6` | 六和弦本版不支持 |
| `5` | 强力和弦本版不支持，请写 `C` |
| `sus` | 请明确写作 `sus2` 或 `sus4` |
| `7sus4`、`7sus2` | 挂留七和弦本版不支持 |
| `mmaj7`、`mM7` | 小大七和弦本版不支持 |
| `alt`、`no3`、`omit3` | 变化音 / 省略音写法本版不支持 |

> **这张表在 2026-09-22 变短了。** 原先 `°` `o` `+` `-` `M` `M7` `Maj7` 七种写法
> 都在报错，现在它们都是**合法别名**（§5.2.1）。
> 去掉它们不等于放宽了和弦范围 —— 表里剩下的每一条都是**乐理范围**问题
> （这些和弦本版根本没有对应 id），与「怎么写」无关。
> 两者的区别就是加一个和弦 id（改动大、要定乐理语义）和加一条别名（改动小、只影响解析）
> 的区别，不要混在一起谈。

## 6. 数字功能谱（级数显示）

### 6.1 大调级数推导算法

只支持**大调**。符号约定：`letterIndex` 为字母在 `C D E F G A B` 中的下标（C=0 … B=6）；
`semitone` 为音名对应的十二平均律序号（C=0）。

```
输入：调号 key = { tonic: (tl, ta) }，目标音 n = (letter, acc)

1. T = semitone(tl) + ta                      调主音的半音序号
2. 级数 degree = ((letterIndex(letter) - letterIndex(tl)) mod 7) + 1
3. 需要的半音 expectSemitone = (T + MAJOR_SCALE[degree - 1]) mod 12
       MAJOR_SCALE = [0, 2, 4, 5, 7, 9, 11]
4. 该级数的字母本身自带的半音 naturalSemitone = semitone(letter)
5. 本调中这一级应有的升降号 expectAcc = signedDiff(expectSemitone - naturalSemitone)
       signedDiff(d) = ((d mod 12) + 12) mod 12，若结果 > 6 则减 12
6. 相对升降号 delta = acc - expectAcc
7. 前缀 = '#' × delta （delta > 0）或 'b' × (-delta)（delta < 0），delta = 0 时无前缀
输出：前缀 + degree + 性质后缀
```

**第 2 步是关键**：级数由**字母到主音字母的字母距离**决定，不是由半音距离决定。
这样 `F#` 在主音 C 时是 `#4`，在主音 G 时是 `7` —— 因为 F 是 G 的第 7 个字母。
按半音距离猜会得到错误答案。

性质后缀沿用 §5.1 的表（大三和弦无后缀）。

### 6.2 示例

C 大调（`C D E F G A B` → `1 2 3 4 5 6 7`）：

| 和弦名 | 级数 | 说明 |
| --- | --- | --- |
| `C` | `1` | |
| `Dm` | `2m` | |
| `Em` | `3m` | |
| `F` | `4` | |
| `G` | `5` | |
| `Am` | `6m` | |
| `Bdim` | `7dim` | |
| `Cmaj7` | `1maj7` | 性质后缀保留 |
| `Am7` | `6m7` | |
| `G7` | `57` | 属七后缀就是 `7`，谱面上画成右下角小角标（§6.6） |
| `F#dim` | `#4dim` | 非调内根音用明确升降级数 |
| `Bb` | `b7` | |
| `Eb` | `b3` | |
| `C/G` | `1/5` | 斜杠低音也转换 |

| 和弦名 | 级数 | 说明 |
| --- | --- | --- |
| `G` | `1` | |

### 6.3 斜杠低音

斜杠低音用同一套算法单独转换，再拼成 `级数/低音级数`：

- C 大调 `G/B` → `5/7`
- C 大调 `C/E` → `1/3`
- C 大调 `F/A` → `4/6`

### 6.4 显示切换不改数据

- 数据显示**哪几行**存在 `layout.displayLines` 里（1–3 项数组，取值见 §8.1.1），只是一个显示偏好。
- 切换显示**不得修改任何和弦字段**。导出的 JSON 里永远只有和弦数据，不出现级数字符串。
- 级数在渲染时按需计算，不缓存进数据。
- **文本导出不受影响**：`songToText` 只写和弦名，与 `displayLines` 无关 ——
  把显示行从「只有和弦名」切到「三行并行」，导出的文本一个字都不会变。

### 6.5 不支持的调式

`key.mode` 目前只接受 `'major'`。

- 校验器会把 `mode !== 'major'` 判为非法，并说明「小调的级数显示尚未实现」。
- **不允许**把小调当成它的关系大调来算级数 —— 那会安静地输出错误结果。
- 和弦名显示（`displayLines: ['chord']`）不受影响，因为没有调式理论参与。
- **级数行会被跳过，但必须给出原因。** 用户勾了「数字级数 / 罗马级数」而调式不是大调时，
  谱面上不画级数行，同时在和弦块上打一个「级数不可用」角标说明原因。
  **只跳过渲染、不改数据** —— 调号改回大调后，原先选中的那几行会自己回来。
  安静地少显示一行，用户只会以为功能坏了。

### 6.6 属七后缀的写法

属七和弦的级数后缀是**纯数字**：`G7` → `57`。两个数字直接相邻，第一眼容易被读成
「五十七」。这是唯一一处「后缀会和根音级数连成一片」的情况，所以需要专门处理 ——
它也是本文档里被反复讨论的一个点（§11 第 8 条）。

四种写法都在现实中有人用，由 `layout.seventhSuffix` 决定：

| `seventhSuffix` | 数字级数 | 罗马级数 | `parts` 切分 | `value` |
| --- | --- | --- | --- | --- |
| `'subscript'`（缺省） | `5` + 小 `7` | `V` + 小 `7` | `[5][7:sub]` | `57` |
| `'plain'` | `57` | `V7` | `[5][7]` | `57` |
| `'superscript'` | `5` + 上标 `7` | `V` + 上标 `7` | `[5][7:sup]` | `57` |
| `'parens'` | `5(7)` | `V(7)` | `[5][(7)]` | `5(7)` |

**不变式（四档都必须成立）**：`parts.map(p => p.text).join('') === value`。

- **`'parens'` 是唯一一个 `value` 里带括号的档。** 另外三档改的只是**排版**
  （`57` 这三个字符的排列方式），括号档改的是**文字本身** —— 括号是这个写法的组成部分，
  把 `5(7)` 那段文字复制走，得到的就是 `5(7)`。这不是疏漏，是这两种改动的本质差别。

三条一直没变的规则：

- **只对属七生效。** 小七 `6m7`、大七 `1maj7`、减三 `7dim`、挂四 `5sus4` 的性质符号里
  带字母，数字不会连成一片，一律按普通文字渲染。`seventhSuffix` 只改「属七写什么」，
  **不改「谁需要特殊处理」** —— 那个范围仍然只有属七一项（§11 第 8 条已拍板）。
- **`'subscript'` 与 `'superscript'` 都要下沉/上浮，`'superscript'` 要说明用途。**
  右下角是缺省，它避开的是「被读成幂」这个误读（上标 `5⁷` 天然会被读成 `5` 的 `7` 次方）。
  仍然提供上标档，是因为确实有人这么写、且不会误读 —— 但不能把它设成缺省。
- **斜杠低音与属七同时出现时后缀不在末尾**（`G7/B` → `5` + `7` + `/7`），
  所以渲染必须**逐段顺序绘制**，不能假设「最后一段才是后缀」。

实现落点：`core/degrees.js` 把级数切成 `parts`（`value` 是纯文本，`parts` 是带 `script`
标记的片段：`null` / `'sub'` / `'sup'`）；屏幕渲染成嵌套 `span`
（样式见 `styles.css` 的 `.deg-sub` / `.deg-sup`），PNG 用更小字号 + 基线偏移逐段绘制。

### 6.7 罗马数字级数

数字级数和罗马级数**不是两套算法**，是同一套算法换字形（`DEGREE_GLYPHS = ['arabic', 'roman']`）：
「字母距离定级数」「本调应有升降号定前缀」两步完全共用，只在最后一步把 `4` 写成 `IV`。
所以两者不可能对同一个和弦给出级数不同的答案 —— 这一条要能一眼从代码里看出来。

**大小写承担了和弦性质**，这是罗马字形与阿拉伯字形最大的差别：

| 和弦性质 | 大小写 | 例子 |
| --- | --- | --- |
| 大三 / 属七 / 大七 / 挂二 / 挂四 / 增三 | 大写 | `I` `V7` `Imaj7` `Vsus4` `Vsus2` `Iaug` |
| 小三 / 小七 / 减三 | 小写 | `ii` `vi7` `vii` |

**`m` 后缀被小写吸收**，不能重复表达：小写 `vi` 已经说明这是小三和弦，再补一个 `m`
就成了 `vim` —— 同一件事在一套字形里说了两遍。所以罗马字形下只有两个后缀改写：

| 性质 | 数字字形后缀 | 罗马字形后缀 |
| --- | --- | --- |
| 小三 `m` | `m`（`6m`） | 省略（`vi`） |
| 小七 `m7` | `m7`（`6m7`） | `7`（`vi7`） |

其余后缀（`maj7` `aug` `sus2` `sus4`）原样保留；`dim` 见 §6.7.1。

#### 6.7.1 减三和弦的后缀：`dim` 还是 `°`

减三和弦的级数后缀有两种都在用的写法，所以这是**第二个有争议、可放开**的点
（另见 §11 第 5 条）。由 `layout.dimSuffix` 决定：

| `dimSuffix` | 数字级数 | 罗马级数 |
| --- | --- | --- |
| `'dim'`（缺省） | `7dim` | `viidim` |
| `'°'` | `7°` | `vii°` |

三条规则：

- **两种字形共用同一个值**，不分开设。设成 `'°'` 时数字行与罗马行**同时**变成 `°` ——
  否则两行并排会出现 `7dim` 与 `vii°` 并存，看着像两个不同的和弦，比不做还糟。
- **`°` 不是角标**。角标规则（§6.6）只作用于属七的 `7`，`°` 是普通后缀、全字号。
- **`°` 不参与罗马数字的大小写规则** —— 它不是字母。`vii` 的小写仍然由和弦性质决定，
  只是后缀从 `dim` 换成了 `°`。

**只在级数行里生效。** `°` 是**级数记法**的后缀，不是和弦性质符号：`dimSuffix` 无论
设成什么，**和弦名都不受它影响**。

> **2026-09-22 补充：那句话里的「将来」到了。** `chordSymbols`（§5.1.1）这个开关已经开了，
> 爵士体系下和弦名确实会写 `C°`。但那是**另一个开关**做的，两个开关各管一段、互不牵连：
>
> | 设置 | 和弦名 | 级数行 |
> | --- | --- | --- |
> | `chordSymbols: 'common'`（缺省）+ `dimSuffix: 'dim'`（缺省） | `Bdim` | `7dim` |
> | `chordSymbols: 'jazz'` + `dimSuffix: 'dim'` | `B°` | `7dim` |
> | `chordSymbols: 'common'` + `dimSuffix: '°'` | `Bdim` | `7°` |
> | `chordSymbols: 'jazz'` + `dimSuffix: '°'` | `B°` | `7°` |
>
> **「两处字形相同、语义不同」这件事本身没变**，变的只是「和弦名那一处现在也有开关了」。
> 这一条必须守住 —— 混淆这两件事会让「显示偏好」渗进「和弦数据」。

实现落点：`chordToDegree(chord, key, glyph, dimSuffix)` 的第四个参数，
由 `formatChordForDisplay` 从 `options.dimSuffix` 传入。屏幕与 PNG 共用这一个关口。

**C 大调对照表**（与 §6.2 同一批和弦，只换字形；**减三那两行按缺省的 `dimSuffix: 'dim'` 写**，
设成 `'°'` 时是 `7°` / `vii°`，见 §6.7.1）：

| 和弦 | 数字级数 | 罗马级数 |
| --- | --- | --- |
| Cmaj | `1` | `I` |
| Dm | `2m` | `ii` |
| Em | `3m` | `iii` |
| Fmaj | `4` | `IV` |
| Gmaj | `5` | `V` |
| Am | `6m` | `vi` |
| Bdim | `7dim` | `viidim` |
| Cmaj7 | `1maj7` | `Imaj7` |
| Am7 | `6m7` | `vi7` |
| G7 | `57` | `V7` |
| F#dim | `#4dim` | `#ivdim` |
| Bb | `b7` | `bVII` |

- **属七的角标规则完全沿用 §6.6**：`V7` 的后缀 `7` 照样画成右下角小角标，
  `G7/B` → `V` + 角标 `7` + `/VII`，角标依然不在末尾。
- **斜杠低音只有音名、没有和弦性质**，所以不参与大小写规则，一律大写（`/VII`）。
- **纯文本仍然是纯文本**：`parts.map(p => p.text).join('') === value` 这条不变式对两种字形
  都成立，所以文本导出、无障碍标签都不受字形影响。
- 小调时罗马行与数字行**一起**跳过（§6.5），不会出现「只剩罗马行」这种半截状态。

实现落点：`pitchToDegreeToken` / `chordToDegree` 各多一个 `glyph` 参数（默认 `'arabic'`），
`formatChordForDisplay` 由 `options.line === 'roman'` 触发。

## 7. 编辑与存储

### 7.1 编辑操作

| 对象 | 操作 |
| --- | --- |
| 歌曲 | 新建、重命名、复制、删除 |
| 段落 | 添加、重命名、复制、删除、上移、下移 |
| 小节 | 插入、复制、删除；设为空白 / 取消空白 |
| 事件 | 添加、修改和弦或休止、删除 |
| 时值 | 修改时值、修改斜杠低音 |
| 拍号 | 修改后重新校验，**不静默改写已有时值** |
| 通用 | 撤销、重做 |

### 7.2 撤销与重做

- 粒度是**一次用户操作**，不是一次字段改动。
- 复制 / 移动元素必须生成新 ID（除非是「撤销」还原），避免 ID 冲突。

### 7.3 本地保存

- 存储位置：浏览器 `localStorage`，键名 `chord-chart-workbench/v1/library`。
- 自动保存，并显示**真实**状态（已保存 / 保存中 / 保存失败），不假装成功。
- 刷新后恢复。
- 保存失败必须可见提示，并允许导出工程备份（localStorage 可能被写满或被浏览器清理）。
- **读取到损坏数据时不能直接覆盖原始内容**：保留原始字符串，提示用户，允许导出或手动清理。
- 切换歌曲前先处理尚未应用的输入草稿，避免丢失。
- 界面上要说明：**浏览器数据不等于永久备份**。

### 7.4 工程文件（JSON）

导出内容：

```json
{
  "schemaVersion": 2,
  "exportedAt": "2026-09-21T12:00:00.000Z",
  "song": { ...完整的 Song 对象... }
}
```

导入流程：

1. 检查体积（上限 4 MB），超限直接拒绝。
2. 解析 JSON，失败给出语法错误。
3. `schemaVersion` 必须是 **2**；若是 `1`，先按下面的迁移表转换再继续校验（见下）。
4. 逐字段校验类型、数值范围、字符串长度。
5. 查重 ID。
6. **任一检查失败 → 当前数据完全不变**，只展示错误列表。
7. ID 冲突（与库中已有歌曲重复）→ **生成新的歌曲 ID**，不覆盖已有歌曲。
8. 用**安全的文本方式**渲染用户数据，绝不拼接不可信 HTML。

**v1 → v2 迁移（只此一处）**

v1 的 `layout.displayMode` 是 `'chord' | 'degree'`，v2 换成了 `layout.displayLines`：

| v1 的值 | v2 的值 |
| --- | --- |
| `'chord'` | `['chord']` |
| `'degree'` | `['degree']` |
| 缺失 / 非法 | `['chord']`（默认） |

迁移是**读取时的转换**：旧字段读进来之后立刻丢弃，**永远不会被写回**。
所以数据里只有 `displayLines` 一个真相，不存在两份互相打架的显示偏好。

**新增可选字段不触发迁移，也不升版本号**

`layout.dimSuffix`（§6.7.1）是在 `schemaVersion = 2` 之后新增的，但它**不升版本号**。
判据只有一条：

> **只有当「老程序读这份新文件会得到与作者所见不同的结果」时才升版本号**
> —— 即字段被**移除**或语义被**改变**。纯新增的可选字段，只要**缺省值等于旧行为**，就不升。

为什么这条判据重要：**升版本号会让老程序直接拒绝整份工程文件**（§7.4 第 3 步）。
为「减三后缀怎么写」这种纯显示偏好，把用户整份工程挡在门外，代价远大于收益。

代价是老程序读到 `dimSuffix: '°'` 时会**忽略**它、显示回 `dim`。这是**可接受的降级**：
丢的是一处观感，不是音乐事实；反过来若升了版本，丢的是一整份文件。

因此 `dimSuffix` 在处理上是**可缺省字段**：缺失等价于 `'dim'`，
读取侧统一用 `normalizeDimSuffix()` 兜底（与 `displayLines` 在渲染关口的容错同一手法）。
校验只要求「若存在则取值合法」，**不要求它存在** —— 这条很关键：
`library.js` 读 `localStorage` 时**直接调 `validateSongShape`、不走迁移**，
若把它设成必需字段，用户已存的每首歌都会在下次打开时被判为损坏并隔离。

## 8. 谱面与导出

### 8.1 谱面内容

标题、艺人、调号、拍号、BPM、备注、段落（名称 / 重复标注 / 演奏提示）、小节、
和弦与演奏提示。

### 8.1.1 显示行（1–3 行并行）

每个和弦块可以同时显示**最多三行标签**，显示哪几行由 `layout.displayLines` 决定：

| 行 | 取值 | 内容（C 大调示例） |
| --- | --- | --- |
| 和弦名 | `'chord'` | `Cm7` |
| 数字级数 | `'degree'` | `1m7` |
| 罗马级数 | `'roman'` | `i7` |

- **至少 1 行、最多 3 行**，不允许重复。
- **顺序固定**为 `chord → degree → roman`（从上到下）。用户只能选「显示哪几行」，
  不能调换顺序 —— 固定顺序让「哪一行是什么」始终可预期，也避免组合数无意义地膨胀。
- 第一行是**主行**（字号最大）；其余为**次行**（字号小一档、颜色略淡）。
- 时值标签（`4 拍`）始终显示在**最后一行之下**，不参与「显示行」的选择。
- **行数只改变块的高度，不改变宽度** —— 宽度永远只由时值决定（§8.2）。
- 数字级数与罗马级数都要求调号是大调（§6.5）。调式不是大调时，这两个选项在界面上
  置灰并说明原因，已被选中的会自动退回只显示和弦名。

### 8.1.2 休止符的写法（`restText`）

休止事件在谱面上写什么字，由 `layout.restText` 决定：

| 取值 | 谱面上 | 适用 |
| --- | --- | --- |
| `'cn'`（缺省） | `休止` | 中文用户，最不容易误解 |
| `'dash'` | `—` | 排版紧凑，长破折号 |
| `'R'` | `R` | 与文本语法一致（§4.2 里休止就是 `R`） |

- **没有 `'0'` 这一档，是刻意的**（理由见 §2.4）：`0` 在本工具的文本语法里已经是
  **空白小节**的记号，同一个字形不能有两个意思。
- **只改谱面上的字，不改数据。** 休止的判定永远是 `event.kind === 'rest'`（§2.4）。
- **不影响文本导出**：导出的文本里休止恒为 `R`（§4.8）。
- 休止**只占一行**，不参与 `displayLines` 的选择 —— 休止没有和弦性质，也没有级数。

### 8.2 排版

- 和弦按时值占据对应的水平空间。实现上：事件块的 `flex-basis` 为 0，宽度只由
  「时值 ÷ 每小节拍数」决定，不受和弦名长短影响。
- 提供每行 **2 / 4 / 8** 小节设置。这是**歌曲设置**，打印和 PNG 严格按它排版。
- **屏幕上可以往下减少每行小节数。** 如果可用宽度放不下这个设置，屏幕（编辑 /
  预览 / 演出）允许把每行小节数降到 **4 → 2 → 1** 中排得下的那一档，判据是
  「一个小节至少 88px」（约两个和弦块各 44px，见 §9）。
  这条有三个约束，缺一不可：
  1. **不改动歌曲数据。** `layout.barsPerRow` 一个字节都不动。
  2. **必须在谱面上写出来**（「现在按每行 N 小节显示」），否则用户会以为设置没生效。
  3. **打印与 PNG 不受影响**，仍按设置排 —— 那边宽度是 A4，没有手机那么窄。
- 空白小节保持和普通小节相同的宽度。
- 超长和弦名折行，不与相邻内容重叠。

### 8.3 分页

- 长歌自动分页。
- **不把一个小节截断到两页。**
- **避免段落标题单独留在页尾**（段落标题要和它的第一个小节同页）。

### 8.4 导出与打印的统一入口

**一个入口，三种出口。** 界面上只有一处「导出与打印」，打开后先选出口，再选页：

| 出口 | 产出 | 文字可选中 | 支持选页 |
| --- | --- | --- | --- |
| 保存为 PDF | 一个 `.pdf` 文件（A4 纵向、多页） | 否（位图） | **是** |
| 保存为图片 | 每页一个 `.png` 文件 | 否 | **是** |
| 浏览器打印 | 交给浏览器（可送打印机或另存） | 是（矢量文字） | **否，整首** |

规则：

1. **能选页的两个出口必须共用同一套分页计算**（§8.3）。面板缩略图里看到的第 3 页，
   就是导出文件里的第 3 页 —— 不允许出现「面板说三页、导出四页」。
2. **「浏览器打印」不支持选页，而且必须在面板里写出来。** 分页由浏览器决定，
   我们无法可靠地「只打第 2 页」；假装能选、实际打整首，比提前说明更糟。
3. **导出内容中去除编辑按钮、选中框、校验提示。**
4. 对存在时值错误的歌曲，**任一出口启动前**都要明确提示用户先处理，
   不静默导出一份已知有问题的谱面。
5. 按钮命名如实表达。**不得**让用户以为按下就会静默下载文件，也不得让用户
   以为「打印」不是「保存为 PDF」的唯一途径。

### 8.5 PDF

**两条路，各自如实命名。**

| 路 | 怎么走 | 取舍 |
| --- | --- | --- |
| **保存为 PDF** | 应用自己生成字节流（`src/core/pdf.js`），**不引依赖** | 内嵌位图，**文字不可选中、不可搜索**；换来手机上也能一键下载，且**能按页选** |
| **浏览器打印** | `window.print()`，在打印对话框的目标里选「另存为 PDF」 | 文字是矢量的、可选中可搜索；但**不能选页**，且要面对浏览器自己的对话框 |

为什么自造 PDF 而不引库：导出内容只有文字、线条和矩形，而「不引依赖」这条
已经在 §11-7 为 PNG 立过。自造 PDF 的代价是**位图化**，这个代价必须写在
界面上 —— 不能让用户拿到一份「搜不到字」的 PDF 还不知道为什么。

自造 PDF 的实现约定：

- 页尺寸 A4 纵向；像素映射与 PNG 导出共用同一份版面（§8.6）。
- 每页内嵌一张 JPEG（PDF 的 `DCTDecode`），**不引入 PNG 的 zlib/预测器处理** ——
  那条路要为「浏览器到底输出 RGB 还是 RGBA」写两套分支，风险大于收益。
- 质量取 0.92 以上。谱面是深灰字 + 白底 + 细线，低于这个值细线会开始抖。
- `pdf.js` 只做「若干张图片字节 + 页尺寸 → PDF 字节」，**不碰 DOM**，所以它
  能在 Node 里直接单测（与 `core/` 的其它模块同一条纪律）。

### 8.6 PNG

- 输出清晰的高分辨率谱面。
- 正确显示中文、升降号和和弦性质。
- **按页选择导出**，不生成一张无限长、难以使用的图片。
- 导出失败必须给出明确的错误信息。

### 8.7 预览与演出

**两个不是一回事，职责不同。**「预览」回答「这份谱排得对不对」，
「演出」回答「台上怎么看得清」。

| | 编辑 | 预览 | 演出 |
| --- | --- | --- | --- |
| 左侧面板与底部工具条 | 有 | 隐藏 | 隐藏 |
| 顶栏内容 | 完整（模式切换 + 撤销重做 + 保存状态） | 完整 | **歌名 + 模式切换**（不留撤销重做和保存状态） |
| 点按能否改数据 | 能 | 不能 | 不能 |
| 谱面字号 | 按 `fontScale` | 按 `fontScale` | **在 `fontScale` 之上再放大** |
| 小节序号 / 拍数标签 | 显示 | 显示 | 缩小到最小标记 |
| 屏幕常亮 | 否 | 否 | **是**（浏览器支持时的可选增强） |
| 找谱（搜索曲库） | 否 | 否 | **是** |

- 预览**保留全部版面信息**，因为它就是用来核对「屏幕上的排版和导出的是不是一致」的。
- 演出**收掉非必要的操作控件**。台上没有注意力分给撤销按钮和保存状态，
  但**模式切换的三个入口必须留着**——否则进了演出就找不到路回编辑 / 预览。
  谱面下方另有一个「返回编辑」兜底，两处都能走。
- 二者都**禁止误触编辑**（点按和弦不弹出编辑面板）。
- 屏幕常亮不支持时不影响核心使用。

### 8.9 歌词（逐字对齐）

和弦 / 休止的**下方**可以挂歌词，逐字对齐到事件。这是本版新增的歌词能力，
数据模型从「只有和弦」扩展成「和弦 + 歌词」。

**数据表达**

歌词**不独立成实体**，挂在 `bar.lyrics` 上，用**事件下标**对齐：

```
bar.events  = [ C:2 , G/B:2 ]
bar.lyrics  = [ {text:'候鸟'}, {text:'飞向南方'} ]
              ↑ 对齐到 C       ↑ 对齐到 G/B
```

- `lyrics[i]` 对应 `events[i]`。`null` 或空串表示该事件下方没有歌词。
- 一个片段可以放**一个或多个音节**；渲染时片段内的字在事件占的水平空间里**均匀铺开**，
  让「字对着和弦」在视觉上成立——不需要用户手动调每个字的坐标。
- `lyrics` 是**可缺省字段**：缺失、或整段为空，都等于「没有歌词」（旧行为）。
  **整小节清空歌词后字段会被整个移除**，不留一个全空数组——「有没有歌词」始终可判定。
- 空白小节（`type === 'empty'`）没有事件，歌词对不上位置，**忽略**。

**编辑与存储**

- **只在谱面点按编辑**：点按和弦 / 休止 → 事件面板里多一个「歌词」输入框，
  填的是这个事件下方的那段词。**文本输入面板的语法不加歌词记号**（§4 保持不变），
  歌词不参与文本解析。
- 歌词跟着小节走：复制小节 / 段落、复制整首歌、克隆，歌词一并带过去（逐字对齐不丢）。
- 序列化进 JSON，工程文件导入导出自动带歌词，往返不丢。
- 事件与歌词的修改合并成**一步撤销**——「改和弦 + 填词」是一次用户操作（§7.2）。

**渲染与导出**

- 屏幕谱面、PNG 导出**共用**同一套歌词渲染规则（和和弦/级数一个纪律，§8）。
- 歌词行显示在小节框内、事件下方，用与事件相同的时值比例占位。
- **没有任何歌词时，不额外占一行**——否则每小节都凭空多出空白，把谱面拉长。
- 小调等「级数不可用」的情形**不影响歌词**：歌词对齐的是事件，与调式无关。

**一条必须说清的边界**

文本输入面板的「解析并应用」会**重写全部段落和小节**。因为歌词不进文本语法，
这一步会**清空已有的歌词**。这是有意取舍（歌词只走点按编辑），必须在界面上
说清楚，不能让它变成「我录好的词怎么没了」的惊吓。

### 8.10 自由文字块（逐行写 + 自由拖拽）

和弦 / 小节的**下方**可以挂**自由定位的文字块**。它和 §8.9 的「逐字对齐歌词」是
**两套并存的机制**，解决的是不同需求：

- **逐字对齐歌词（§8.9）**：字**跟和弦强绑定**，系统自动均匀铺开，用户不碰位置。
- **自由文字块（§8.10）**：文字块**自由定位**，用户手动拖到任意位置、逐行写，想放哪放哪。

两者**不打架**：歌词负责「唱词」，文字块负责「标注 / 提示 / 想自由摆的文字」。

**数据表达**

文字块挂在 `bar.textBlocks` 上，是一个**可缺省**数组。每个块：

```
textBlock = { id: 'txt_…', text: '副歌第一遍\n转调前', x: 0.5, y: 0.8, anchor: 0 }
             └ 文字，可 \n 换行      └ 水平 0–1   └ 垂直 0–1   └ 对齐到第 0 个和弦；-1 = 小节级
```

- **`x` / `y` 用 0–1 比例，不是像素。** 这是本功能最重要的一条纪律：屏幕、PNG 导出、
  打印共用同一份坐标，只有用比例，文字块才不会「手机上对好了、导出去全歪了」。
  渲染时拿「小节框实际宽高 × 比例」换算成像素。
- **`anchor` 决定文字块跟谁走。** `anchor = 事件下标` 表示绑定到那个和弦；`-1` 表示
  小节级、不跟任何和弦。和弦被删除或移动时，绑定到它的文字块要**跟随调整**：
  - 删掉 `events[k]` 后，`anchor > k` 的块 `anchor -= 1`；`anchor === k` 的块降级为
    `anchor = -1`（和弦没了，退成小节级，文字不丢）。
  - 移动（交换）两个和弦时，文字块的 `anchor` 跟着它绑定的和弦一起换。
- **空串的块不落盘**：`text` 为空的块是「还没写字的占位」，不算真数据，一律不写进
  `textBlocks`（和 §8.9 里「整小节清空歌词就整个移除字段」是同一条纪律）。

**两种粒度（一个开关）**

编辑文字块有两种粒度，由 `layout.textBlockMode` 控制：

| 取值 | 含义 |
| --- | --- |
| `'bar'`（缺省） | **按小节写**：一个小节一个大文本框，写整段词。块默认 `anchor = -1`、`x = 0`、`y = 0`，占满小节宽度。 |
| `'chord'` | **按和弦写**：每个和弦下方单独一个小框，分别写字。块默认 `anchor = 对应和弦下标`。 |

- 切换模式**只改变「新建块时的默认锚点和位置」**，**不改变已有块**——已有的文字块
  原样保留，用户已经拖好的位置不会被一次切换毁掉。
- `layout.textBlockMode` 是**可缺省**字段，缺省等于 `'bar'`（等于旧行为——没有文字块功能时）。

**编辑与存储**

- 编辑入口在**小节面板**里加「文字块」区：新增块、编辑块文字（支持 `\n` 逐行写）、
  删除块。
- **拖拽**：编辑模式下，文字块可以直接拖动，松手时把像素位置换算回 0–1 比例写入 `x` / `y`。
  拖拽更新的是位置，文字内容仍走面板编辑（拖拽不弹输入框，避免拖动误触发打字）。
- 文字块跟着小节走：复制小节 / 段落、克隆，文字块一并带过去（ID 重新生成，`x` / `y` /
  `anchor` 保留）。
- 序列化进 JSON，工程文件导入导出自动带文字块，往返不丢。
- 一次拖拽松手 = 一步撤销；一次文字编辑 = 一步撤销（§7.2）。

**渲染与导出**

- 屏幕谱面、PNG 导出、打印**共用**同一套渲染规则（§8 的纪律）。
- 文字块是绝对定位浮层，`x` / `y` 按比例换算成实际坐标；文字可多行（`\n` 换行）。
- **文字栏**：文字块默认落在小节框**下方**，不是飘在框正中间。有文字块的小节，底部
  预留一块「文字栏」高度（`.bar--has-text` 加 `padding-bottom`），给字一个明确的下方落脚点，
  字不会盖住和弦。`x` 水平居中、`y` 默认 `0.8` 落到下方那一行，文字从顶部往下长。
- **字号**：文字块的字**必须大、必须一眼看清**（`1.15em` 起），是谱面的主角之一。
  和弦可以小，字不能小。PNG 导出用和弦主行同档字号（`symbolSize`）画文字块。
- **不竖排**：文字块默认 `white-space: nowrap`，字**横着延伸出去**，绝不自动折行
  （长文本不会一个字占一行竖起来）。只有用户手动敲回车才换行。
- 空白小节（`type === 'empty'`）**也允许文字块**——「间奏」「转调」这类标注就写在空白小节上。
- 没有文字块时，不额外占高度（不触发文字栏的 `padding-bottom`）。

**与「解析并应用」的关系**

和歌词一样，文字块**不进文本输入语法**。文本输入面板的「解析并应用」会重写全部段落，
文字块会**一并清空**。界面上要在确认框里说清（和 §8.9 那条边界一致）。

## 9. 界面规则

视觉方向：米白 / 浅灰工作区、白色谱纸、深灰文字、低饱和绿色强调色。
不做后台仪表盘，不堆砌无意义卡片和图表。

| 场景 | 布局 |
| --- | --- |
| 桌面 | 歌曲信息与编辑工具在一侧，谱面预览在另一侧。 |
| 手机 | 「编辑 / 预览」切换；常用操作靠近底部；点按和弦打开底部编辑面板。 |
| 平板 | 按可用宽度在分栏和单栏之间切换。 |

硬性要求：

- 常用触控目标 ≥ 44px。
- 不依赖鼠标悬停才能使用。
- 排序提供**点按移动**，不能只支持拖动。

关于 44px 与 §8.2 的比例规则如何共存（这两条天然会打架）：

- **控件**（按钮、输入框、选项、面板条目）一律硬性 ≥ 44px，没有例外。
- **和弦块**的宽度由时值比例决定（§8.2），不强制 44px —— 否则「按时值占位」
  这条就废了。但**正常情况下应能点准**，所以屏幕允许按 §8.2 降档折行，
  使一个「一小节两个和弦」的普通小节里，每个和弦块仍有 ≥ 44px。
- 已知边界：一个小节里挤了 3 个以上等长事件时，和弦块会低于 44px。这种小节
  **本来就违反时值规则**（Σ 拍数超过小节容量），界面上已按 §3 标红提示。
  这是刻意的取舍 —— 不为了一个已经报错的状态去牺牲正常情况的排版。
- 软键盘不遮挡正在编辑的字段和提交按钮。
- **不让整个页面出现横向滚动。** 不允许用 `overflow-x: hidden` 把溢出藏起来。
- 有清楚的输入标签、焦点状态和错误提示。

### 9.1 信息层级（左栏放什么）

左侧面板**不做「把所有功能平铺出来」的清单**。规则：

| 位置 | 放什么 | 为什么 |
| --- | --- | --- |
| 左栏顶部（默认展开） | 歌曲信息与谱面设置 | 编辑时持续要用 |
| 左栏中部（默认折叠） | 曲库、文本输入 | 用得着但不常驻，折叠起来降低视觉噪声 |
| 左栏最下方（默认折叠） | **数据**：导入 / 导出工程 JSON、导出与打印、危险操作 | 低频且彼此相关，合成一处 |

- **「导入工程」和「导出工程」必须挨着放** —— 它们是一件事的两端。
- **「导出与打印」收在同一个「数据」区里**，不再单独占一个面板（§8.4）。
- 折叠用原生 `<details>`，**折叠起来的依然可达**（键盘能聚焦、能展开）。
  不允许用「删掉功能」来换取清爽 —— 那是把成本转给用户。
- 窄屏（底部面板形态）要给同一个「数据」区留入口。**不允许出现
  「桌面能导出、手机找不到导出」这种能力差异**：视口只改变控件放在哪，
  不改变能做什么（这是本应用从阶段三起的一条硬约束）。

### 9.2 主题与字体（全局偏好）

**主题是整个应用的外观，不是某首歌的音乐事实** —— 所以它**不进 `song.layout`、
不进工程文件、不跟歌走**，而是存在一份独立的**全局偏好**里（localStorage 单独键，
与曲库隔离）。

| 项 | 说明 |
| --- | --- |
| 存储位置 | localStorage 键 `chord-chart-workbench/v1/prefs`，**与曲库键分开** |
| 作用范围 | 整个应用的界面 + 打印 + PNG / PDF 导出的颜色 |
| 跟随性 | 跟**设备**走，换歌、分享工程文件都不变 |
| 缺省 | 护眼绿配色 + 无衬线字体（等于引入主题之前的观感） |

**配色方案（三套）**，每套是一张完整色表，屏幕（CSS 变量）、打印（同一份 CSS）、
PNG / PDF 导出（Canvas 读同一张表）**共用**：

| 方案 id | 名字 | 特点 |
| --- | --- | --- |
| `green` | 护眼绿（默认） | 米白工作区 + 低饱和绿强调，当前默认 |
| `mono` | 黑白 | 白底黑字，无彩色，最常规的打印观感 |
| `pure` | 纯白 | 全白背景、极简对比，接近「白纸」 |

色表覆盖的键与 CSS 变量一一对应：`bg` / `paper` / `paperAlt` / `ink` / `inkSoft` /
`line` / `lineStrong` / `accent` / `accentInk` / `accentSoft` / `danger` / `dangerSoft` /
`warn` / `warnSoft` / `warnLine`。**色表是唯一的颜色真相** —— CSS 变量和 Canvas 的
`COLORS` 都从它派生，不允许在渲染代码里再写死一个十六进制值。

**字体（三档）**，同样贯穿屏幕与导出，全部走系统字体、**不引外部字体文件**
（避免导出缺字）：

| 字体 id | 名字 | 谱面观感 |
| --- | --- | --- |
| `sans` | 无衬线（默认） | system-ui 系，当前默认 |
| `serif` | 衬线 | 宋体 / Times 系，更接近印刷谱 |
| `mono` | 等宽 | 等宽字体，和弦对齐更整齐 |

规则：

1. **主题不进 `validateSongShape`、不进 `song.layout`** —— 它是应用层偏好，
   跟音乐数据无关。这样「改主题」永远不会触发「这首歌被判损坏隔离」。
2. **导出颜色必须随主题**：用户切到「黑白」后导出 PNG / PDF，导出的谱面
   也得是黑白的。屏幕、打印、导出三者不能各说各话。
3. 主题偏好**读时容错**（认不出的值退化到缺省），与 `layout` 风格字段同一纪律。
4. 主题是**设备级**偏好，不在工程文件的导入导出范围里。

| # | 问题 | 当前处理 |
| --- | --- | --- |
| 1 | 「艺人或备注」是一个字段还是两个？ | 拆成 `artist` + `notes`，见 §2.2 说明。 |
| 2 | 长行如何续行（一行写不完一个小节很多事件）？ | 本版没有续行语法。需要时用 `\|` 在同一行继续写，或拆成多个小节。 |
| 3 | 是否要「和弦名与级数同时显示」？ | **已定（2026-09-21）**：升级成 `displayLines` 数组，最多三行并行（`chord` / `degree` / `roman`），见 §8.1.1。`displayMode: 'both'` 这个枚举值不再需要。 |
| 4 | 6/8 是否需要「大拍」显示模式？ | 本版固定按八分音符计，界面写明。 |
| 5 | `repeat` 是否在后续版本展开成实际小节？ | 本版坚持只作标注。 |
| 6 | 小调级数如何推导（自然小调 / 和声小调）？ | 未实现，校验器明确拒绝。 |
| 7 | PNG 导出用哪个依赖？ | **已定：不引依赖**，用 Canvas 2D 手绘（`src/ui/png.js`）。理由是导出内容只有文字、线条和矩形，浏览器原生的 `fillText` / `strokeRect` 足够，且直接继承系统字体，**中文与升降号不会出现字体缺失**；引入截图类库反而要带上几百 KB 且要额外处理字体加载时机。分页规则见 §8.3：按 A4 比例 900×1273（可 2.5× 放大）切页，小节不跨页。 |
