# 功能谱工作台：开源选型与产品对标

调研日期：2026-10-09。状态：方案阶段，尚未接入项目或进行浏览器验收。

## 结论

采用「成熟产品的核心使用流程 + 现成的乐谱格式与内核 + 本项目的中文触控界面」路线。已有代码先核验复用；解析器、排版、音频时钟、PDF 文件编码、指法图、图标、字体等，优先选用已存在的实现。

本轮查阅了二十多个 GitHub 候选及五类成熟产品的官方资料，并下载了核心候选的源码和许可证。下面的“支持”主要表示官方文档或源码可确认；不表示已经在我们的程序里跑通。

**修订前一稿：暂不采用自定义逐音符 JSON 作为主要交换格式。** 优先复用 ChordPro / ChordMark 处理和弦与歌词，Sparks NMN 处理中文简谱。若需要所有 AI 返回同一种外形，只增加一个很小的 JSON 包装来携带格式名、原文和疑点，不重新定义整套记谱语言。

## 3. 中文简谱：确实有现成内核

### 首选验证：Sparks NMN

上游：[yezhiyi9670/sparks-notation-1](https://github.com/yezhiyi9670/sparks-notation-1)，Apache-2.0。

已根据[官方和弦文档](https://notation.sparkslab.art/docs/tutorial-annotation/annotations)与[歌词文档](https://notation.sparkslab.art/docs/tutorial-basics/adding-lyrics)确认：有音名/数字/罗马和弦标记、中文逐字与英文逐词歌词、歌词占位、连音相关对齐，以及版式调节。

本轮已获取源码，固定检查提交 `e3b1e928894fa4dfd2e9ff275b4a42276f4232f9`。`packages/core/package.json` 标为 1.15.9。源码 `packages/core/index.ts` 暴露 `parse`、`render`、`paginize`、点击位置回调以及小节高亮定位。

实际接入边界：

- 内核输出 DOM，不能直接当成 SVG 交给 svg2pdf。
- 内核可与现有网页结合，但仓库不是一个已经独立打包好的通用 npm 渲染组件，需要按其 workspace 组织做小范围适配。
- 上游的编辑器偏文本操作；手机点按和弦、改歌词的交互仍需我们做。
- 源码里的 `react-editor` 是可参考/复用的编辑与播放组件；不因此自动把现有整个项目改成 React。
- 官方首页部分能力是状态列表；仅出现功能名称不足以判断已完成。本报告只把详细文档/源码明确支持的内容当作证据。
- 精确显示、移动端触控、字体加载、分页、播放联动和源码往返修改仍需真实试验。

## 7. AI 导入的修订方案

用户仍然只操作一次复制和一次粘贴。建议固定外层如下：

```json
{
  "format": "qingpu-import",
  "version": 1,
  "notation": "chordpro",
  "content": "{title: 微风练习}\n{key: C}\n{time: 4/4}\n{capo: 0}\n{start_of_verse: 主歌}\n[C]微风[Am]轻唱\n{end_of_verse}",
  "issues": []
}
```

- 只含和弦歌词：content 使用 ChordPro。该格式已把和弦放在对应歌词前面，不依赖空格对齐。
- 有明确简谱：优先验证 content 使用 Sparks NMN。它已有音符、歌词、和弦标注和时值语法。
- 需要保留更详细和声节奏而无旋律：比较 ChordMark 是否比基本 ChordPro 更适合，再冻结正式协议。
- notation 指明采用的现成格式；外层格式固定，图中缺失或看不清的内容放入 issues。
- JSON 包装是本程序的轻量入口，不是新行业标准；内部 content 可独立导出为对应现成格式。
- 仍接受直接粘贴 ChordPro / Sparks NMN 原文；不强制所有用户都套 JSON。
- 不要求外部 AI 凭记忆懂冷门语法：复制按钮必须附带选用语法的说明和原创例子。
- AI 输出到程序还要经过真实解析器验证。格式正确不等于识谱正确；缺失旋律、节奏和调号不能自动补成确定事实。

Sparks NMN 与 ChordPro 不具备所有信息的无损互转能力。转换时必须保留原始文件；降级导出丢失旋律、拍点或特定记号时，明确列出丢失项。

## 8. 推荐实施顺序

1. **用真实需求比较内核**：同一份原创样例，验证中文对齐、小调/转位、双行级数、无节奏和弦歌词、带简谱、移动点击定位、A4 分页与 PDF。主要比较 ChordSheetJS / ChordMark，以及 Sparks NMN / simple-notation / JianpuRender。
2. **确定少量主要依赖**：每类职责选一个主要实现，保留官方许可证与固定版本。只下载不等于已接入。
3. **完成制谱闭环**：复用现有曲库/保存/撤销基础，接入选定解析和排版内核，做手机与平板的可视化操作，打通 AI 文本到导出。
4. **补齐简谱与练习功能**：把真实拍点、旋律、和弦、歌词高亮同步起来，接入现成播放组件；节奏未知时让用户选择练习节奏。
5. **完成成熟产品的管理与演出能力**：曲单、批注、回收站、备份、排序筛选和演出阅读。账号同步、PDF 原图浏览、专业六线谱作为明确的扩展范围另排优先级。

下一轮的首个验收样例应当包含：两页 A4、中文歌词、C/Am/F/G、一个斜杠和弦、一段小调、变调夹、一个跨小节延音、一字多音、一个模糊待确认位置。用它选择能少写代码又正确的方案。
